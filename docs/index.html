A lazy web-chore watcher powered by cloud browsers and local open-weight AI.

Describe in plain English what you care about. A cloud browser visits on schedule. If the page hasn’t changed, SlothWatch does nothing. When it does, local Gemma decides if it actually matters—buzzing your phone via ntfy only when it's real.

Quick Install & Run Node.js 20+ 
# 1. Clone & install
git clone https://github.com/dibyendu-coder/slothwatch.git
cd slothwatch && npm install && npm run build
cp .env.example .env

# 2. Check local setup & credentials
npm run doctor

# 3. Add a watch
node dist/bin/slothwatch.js add "https://books.toscrape.com/catalogue/a-light-in-the-attic_1000/index.html" \
  --name "Book Price" --care "Notify if price drops below 50 pounds"

How It Works in 4 Steps

Split architecture: deterministic navigation in the cloud, intelligent reasoning strictly on your machine.

01

Deterministic Navigation

Browserbase cloud instances run headless Chromium via Stagehand to load target pages, handle complex JavaScript, and replay recorded click actions with 0 LLM calls.

Cloud Browser (Browserbase)
02

Lazy Hash Guard

Visible text is normalized and hashed with SHA-256 against the stored SQLite baseline. If the hash matches, SlothWatch exits immediately—consuming 0 tokens and 0 model time.

Lazy First (SHA-256)
03

Compact Diff Engine

When content shifts, a unified line diff strips away thousands of unchanged boilerplate lines, isolating only the genuine textual additions and deletions for context efficiency.

Token Saver
04

Local Gemma Reasoning

A local open-weight model (gemma4:e2b via Ollama) evaluates the diff against your plain-English instructions. Timestamps and noise are suppressed; real changes push to ntfy.

Local AI (Ollama + ntfy)

Why gemma4:e2b is the Default

It delivered a 0% False Negative rate—it never missed a real change the user cared about. It strictly adhered to the JSON schema on the first attempt (0 retries), and clocked in at 5.31s average latency on local CPU/GPU with only 4.6 GB memory required.

Honest Limitations

What SlothWatch does not do and known edges encountered during development.

01

Cold Model Inference Latency

When Ollama first reads quantized model weights from local disk into RAM, the initial inference takes ~30–60 seconds. Subsequent warm evaluations drop to 2–6 seconds.

02

Client-Side Hydration Delays

Heavy single-page applications (SPAs) rendering dynamic tables via client-side fetch may require a CSS selector target or brief sleep step to ensure complete text extraction.

03

Aggressive Bot Verification

While Browserbase cloud browsers bypass most fingerprinting defenses, aggressive CAPTCHAs (like Cloudflare Turnstile interactive checks) can occasionally require manual cookies.

04

Small Model Arithmetic Limits

As verified in benchmark Case 22, 2B parameter models can fail arithmetic comparisons (e.g. judging whether $325 is below $300). Care prompts should specify relative shifts ("if price drops") rather than fine math.

05

Strictly Read-Only Watching

SlothWatch deliberately does not submit forms, enter passwords, or make payments. It is an autonomous observer, not an automated web actor.
